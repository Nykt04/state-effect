Introduction to State

Section 1.1

Understanding State in React

State is a built-in React object that stores data or information about a component. It represents the parts of an application that can change over time based on user action, network responses, or timers.

In standard JavaScript, if you update a normal variable, the user interface does not automatically update to reflect that change. React needs a way to know when data changes so it can redraw (re-render) the screen. State acts as the memory of a component. When state is updated, React knows it must re-render the component to keep the UI in sync with the data.

VariableVsState.js 
// [Ineffective] Normal Variable: React never knows to redraw UI
let count = 0;
count = count + 1; // Mutates in RAM, but screen UI remains stale!

// [Effective] React State: Preserves value between renders + triggers UI update
import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);

  // Calling setter preserves memory AND schedules a UI re-render
  const handleIncrement = () => {
    setCount(count + 1);
  };

  return <button onClick={handleIncrement}>Count: {count}</button>;
}
Section 1.2

Using the useState Hook

useState is a React Hook that allows you to add state variables to functional components.

You call useState at the top level of your component. It takes one argument (the initial state) and returns an array with two elements: the current state value and a function to update that state. We typically use array destructuring to assign names to these two elements.

1st Element (`name`): The current state value stored by React. On the very first render, it equals the initial state (`'Guest'`).
Greeting.jsx 
import { useState } from 'react';

function Greeting() {
  // name is the state value, setName is the updater function
  const [name, setName] = useState('Guest');

  return (
    <div>
      <p>Hello, {name}!</p>
    </div>
  );
}

Section 1.3

Handling User Events

Event handling in React involves capturing user interactions (like clicks, typing, or hovering) and executing a specific function in response, usually to update the state.

React elements have built-in event listener props like onClick, onChange, and onSubmit. You pass a function to these props. When the user interacts with the element, the function fires, triggering the state updater function to modify the UI.

Counter.jsx 
import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);

  // Event handler function
  const handleIncrement = () => {
    setCount(count + 1); // Updates state, triggering a UI refresh
  };

  return (
    <div>
      <p>You clicked {count} times</p>
      {/* Passing the handler to the onClick event */}
      <button onClick={handleIncrement}>Click me</button>
    </div>
  );
}

More on State

Section 2.1

Updating State

State updating is the process of replacing the old state with a new state using the setter function provided by useState. State in React is immutable; you must never modify it directly (e.g., count = count + 1), but instead always use the setter.

When dealing with complex state like arrays or objects, you must create a new copy of the object or array and pass that to the setter function. Furthermore, if your new state depends on the previous state (like incrementing a number), it is safest to pass an updater function to the setter. This ensures you are always calculating the new state based on the most recent version of the state, avoiding bugs during rapid updates.

ScoreBoard.jsx 
import { useState } from 'react';

function ScoreBoard() {
  const [score, setScore] = useState(0);
  const [player, setPlayer] = useState({ name: 'Alice', level: 1 });

  const increaseScore = () => {
    // Updater function: guarantees we use the latest state
    setScore(prevScore => prevScore + 1); 
  };

  const levelUp = () => {
    // Updating an object: spread the old object, then overwrite the specific property
    setPlayer(prevPlayer => ({ ...prevPlayer, level: prevPlayer.level + 1 }));
  };

  return (
    <div>
      <p>{player.name} is Level {player.level} with {score} points.</p>
      <button onClick={increaseScore}>Add Point</button>
      <button onClick={levelUp}>Level Up</button>
    </div>
  );
}

Section 2.2

Understanding How State Changes Trigger Re-rendering

A re-render is React's process of calling your component function again to generate a new version of the UI based on updated state or props.

When you call a state setter function, React compares the new value to the old value using Object.is (strict equality). If the values are identical, React does nothing. If the values are different, React schedules a re-render. It calls the component function from top to bottom, calculates the new JSX, compares it to the existing DOM, and updates only the HTML elements that actually changed.

RenderLogger.jsx 
import { useState } from 'react';

function RenderLogger() {
  const [toggle, setToggle] = useState(false);

  // This console.log runs every time the button is clicked 
  // because the state change forces the function to execute again.
  console.log('Component is rendering! Toggle is:', toggle);

  return (
    <button onClick={() => setToggle(!toggle)}>
      {toggle ? 'On' : 'Off'}
    </button>
  );
}

How to Deal With Side Effects

Section 3.1

Introduction to the useEffect Hook

A side effect (or "effect") is any operation that interacts with the world outside the component, such as fetching data from an API, manually modifying the DOM, or setting up a subscription. useEffect is the Hook that lets you synchronize a component with an external system.

React components should primarily be pure functions that take props/state and return JSX. Side effects belong inside useEffect. The code inside useEffect runs after the component has rendered and the screen has been updated, ensuring that heavy operations or data fetching do not block the UI from appearing.

TitleUpdater.jsx 
import { useState, useEffect } from 'react';

function TitleUpdater() {
  const [clicks, setClicks] = useState(0);

  // This effect reaches outside React to modify the browser tab title
  useEffect(() => {
    document.title = `Clicked ${clicks} times`;
  });

  return <button onClick={() => setClicks(clicks + 1)}>Click Me</button>;
}

Section 3.2

Understanding the Dependency Array

The dependency array is an optional second argument passed to useEffect. It is an array of state variables or props that the effect depends on, dictating exactly when the effect should re-run.

1. No Array 
useEffect(() => {
  ...
});

Runs after every render (initial mount + every single re-render).

2. Empty Array `[]` 
useEffect(() => {
  ...
}, []);

Runs only once after the initial render (when the component mounts).

3. Array with Values `[x, y]` 
useEffect(() => {
  ...
}, [x, y]);

Runs on the first render, and subsequently only if `x` or `y` have changed since the last render.

UserProfile.jsx 
import { useState, useEffect } from 'react';

function UserProfile({ userId }) {
  const [userData, setUserData] = useState(null);

  useEffect(() => {
    // This fetch only happens when the component first mounts, 
    // AND whenever the 'userId' prop changes.
    fetch(`https://api.example.com/users/${userId}`)
      .then(response => response.json())
      .then(data => setUserData(data));
  }, [userId]); // Dependency array

  if (!userData) return <p>Loading...</p>;
  return <div>{userData.name}</div>;
}

Section 3.3

Using Effects and Cleanup Function

The cleanup function is an optional function you can return from inside your useEffect. It tells React how to stop or undo whatever the effect started.

When an effect creates a continuous process—like a WebSocket connection, an event listener on the window, or a timer (setInterval)—that process needs to be destroyed before the component is removed from the screen (unmounted) or before the effect runs again. Otherwise, you will create memory leaks and duplicate behaviors.

Timer.jsx 
import { useState, useEffect } from 'react';

function Timer() {
  const [seconds, setSeconds] = useState(0);

  useEffect(() => {
    // 1. Setup the effect (Start the timer)
    const intervalId = setInterval(() => {
      setSeconds(prev => prev + 1);
    }, 1000);

    // 2. Return the cleanup function
    return () => {
      // This clears the timer when the component unmounts
      // or before the effect re-runs.
      clearInterval(intervalId);
    };
  }, []); // Empty array means this sets up once on mount

  return <h1>Time spent: {seconds} seconds</h1>;
}
